# v0.7 builtins & operators — behavior summary

Complete behavior reference for everything **added or altered** in the v0.7
milestone: 25 new builtins + the 4 comparison operators (`<` `>` `<=` `>=`,
which now also accept booleans). Intended as the source material for the
final user-facing documentation. Semantics are *defined by*
`v0.7-contracts.md`; this file restates the observable behavior with
concrete examples (pinned by the shared suites, the differential suite, and
naive's `test/v0.7-functions.test.ts`) and implementation detail the
contract is silent on (cited from the code).

**Agreement**: naive and nova produce identical observable behavior (values,
exact error messages, RNG consumption) for everything here, except the one
flagged divergence (`all?/1`, compat.md #1 — nova short-circuits, naive
eager; both sides pinned). Every example below evaluates to the shown result
on **both** implementations.

## Conventions

- **Laziness of parameters.** "Eager" (E) for a list/sequence/callable-typed
  parameter means the *argument value* is forced and type-checked at call
  time (wrong type → the call-argument-type-mismatch error, key 21, e.g.
  `调用的第 1 个参数类型不匹配：期待类型「列表」与实际类型「整数」不符`).
  The **elements** of an eager list stay lazy handles (thunks) — "eager
  list" never means the elements are evaluated. `$lazy` (L) parameters are
  passed as unevaluated boxes and only forced where stated.
- **"Forces"** = forces and propagates: an error surfacing while forcing is
  the error of the whole call, unless stated otherwise (sequence terminal
  errors).
- **Implicit casts** apply where the parameter/element spec doesn't include
  the sequence types: `sequence$sum` → its integer sum, plain `sequence` →
  its list. This works for whole arguments (`min(3#d6)`, `count(3#d6)`) and
  per element (`has?([d1], 1)`, `min([d6])`, the flatten listness test,
  `flatMap` results).
- **Returned lists copy element handles**: elements of the result stay lazy
  unless a rule forces them.
- zh strings are quoted exactly as rendered by the default locale.

New (additive; runtime range continues at 50):

| 52 | `UNFOLD_STEP_LIST_LENGTH_MISMATCH` | `传入 unfold/2 的闭包返回的列表应含两个元素，实际含 N 个。` |

## Scalar / utility

### `abs/1`

- **Signature**: `abs(n: integer)` → `integer` (eager scalar).
- **Happy path**: absolute value. `abs(-5)` → `5`; `abs(-9007199254740991)`
  → `9007199254740991` (works at the ±(2⁵³−1) boundary).
- **Edges**: none beyond the integer-range enforcement every integer
  operation has.

### `count/1`

- **Signature**: `count(list)` → `integer` (eager list).
- **Happy path**: list length **without forcing any element**:
  `count([1 // 0, 2])` → `2`; `count(3#d6)` → `3` (sequence$sum argument
  casts to its list; the `#` body thunks are created per position but never
  called, so no dice are drawn).
- **Edges**: `count([])` → `0`. Element values and element errors are
  irrelevant — except for lists *poisoned* by naive's `map`/`zipWith`
  error-beacon quirk, which can still error in naive (pre-existing div9,
  compat.md #9; nova's uniform laziness never does).
- **Laziness**: no element is ever forced.

### `has?/2`

- **Signature**: `has?(list, x: integer | boolean)` → `boolean`; both
  parameters eager (the declaration spec of `x` is `{integer, boolean}`).
- **Happy path**: membership scan, elements forced left-to-right (with
  implicit casts), first equal element → `true`. `has?([1, 2, 3], 2)` →
  `true`; `has?([true, false], false)` → `true`; `has?([], 1)` → `false`;
  `has?([1, 2, 3], 4)` → `false`.
- **Owner's call (strict-scalar rule)**: a scanned element of the *other*
  scalar type is simply **unequal, not an error** (unlike `==`):
  `has?([true], 1)` → `false`, `has?([1, 2], true)` → `false`.
- **Edges**: a non-scalar element (after implicit casts) → key 50
  `传入的列表存在非「整数或布尔」项` (`has?([[1]], 1)`); an element that
  errors *while being forced* propagates that underlying error instead.
- **Laziness / RNG**: short-circuits at the first match — later elements are
  never forced. `has?([1, 1 // 0], 1)` → `true` (the errored tail is never
  touched), and in `[has?([1, d6], 1), d6]` the short-circuit consumes
  exactly one draw, so the trailing `d6` is the stream's **second** draw
  (pinned agreement row).
- `sequence$sum` elements cast to their sum before comparison:
  `has?([d1], 1)` → `true`, `has?([d1], 2)` → `false`.

### `min/1` / `max/1`

- **Signature**: `min(list)` / `max(list)` → `integer` (eager list).
- **Happy path**: integer aggregation, like `sum`/`product`. `min([3, 1, 2])`
  → `1`; `max([3, -1, 2])` → `3`; singleton `min([5])` → `5`. A
  `sequence$sum` argument casts implicitly: `min(3#d1)` → `1`.
- **Owner's call**: integer lists **only** — booleans are NOT accepted
  (unlike `sort/1`). This is an aggregation, not a comparison.
- **Edges**: empty list → key 44 `列表为空`; a non-integer element (after
  implicit casts) → key 45 `传入的列表存在非「数字」项` (`min([true])`,
  `max([1, true])`). Elements are forced left-to-right; an element error
  propagates as such.
- **Laziness**: forces every element up to (and including) the offending one
  on the error path; on success all elements.

### `all?/1`

- **Signature**: `all?(list)` → `boolean` (eager list).
- **Happy path**: conjunction over all leaves, flatten-DFS like `any?/1`
  (nested lists are spliced). `all?([])` → `true`; `all?([true, true])` →
  `true`; `all?([true, false])` → `false`;
  `all?([[true], [false, true]])` → `false`; `all?([[[true]]])` → `true`.
  (naive's `flattenListAll` indexing bug was fixed in naive in v0.7, so
  nested shapes agree on both sides — compat.md #9 bullet 1 retired.)
- **Edges**: a non-boolean leaf → key 46 `传入的列表存在非「布尔」项`
  (`all?([1])`, `all?([[true], 1])`).
- **div1 — the one deliberate divergence (compat.md #1)**: **nova
  short-circuits at the first `false`** — leaves after it are never forced;
  **naive flattens eagerly** (its own `any?/1` style). Pinned both ways:
  - `all?([false, 1 // 0 > 0])` → nova `false`, naive
    `操作 “1 // 0” 非法：除数不能为零`;
  - `all?([false, 5])` → nova `false`, naive key 46;
  - `[all?(3#(d100 > 5)), d100]` → the `all?` boolean agrees on every seed,
    but the trailing draw shifts in nova whenever an early `false` skipped
    draws (pinned per seed: seeds 0/42 agree, seed 1 gives nova `84` vs
    naive `90`).
  Making naive's `any?`/`all?` short-circuit too would retire div1
  entirely — flagged to the owner, not decided.

## Ordering / list reshaping

### `sort/2`

- **Signature**: `sort(list, f: callable)` → `list` (both eager).
- **Happy path**: stable sort by comparator `f(x, y) → boolean`, where
  `true` means "x comes no later than y" (Elixir `<=` style). `sort([3, 1,
  2], |$a, $b| $a <= $b)` → `[1, 2, 3]`; `sort([3, 1, 2], |$a, $b| $a >=
  $b)` → `[3, 2, 1]`; booleans sort too (`sort([true, false], |$a, $b| $a
  <= $b)` → `[false, true]`); `sort([], …)` → `[]`. Stability — equal keys
  keep their original relative order: `sort([[1, 2], [1, 1]], |$a, $b|
  at($a, 0) <= at($b, 0))` → `[[1, 2], [1, 1]]`.
- **The comparator must be pure.** Comparison order/count is an
  implementation detail (naive: hand-written top-down stable merge sort;
  nova: bottom-up stable merge sort) — a comparator that consumes RNG or
  errors only sometimes is **unspecified**; the suites pin only pure
  comparators and always-erroring ones (same error value regardless of
  pair).
- **Edges**: a comparator result that isn't a boolean → key 48, position 2:
  `sort([2, 1], |$a, $b| $a + $b)` →
  `作为第 2 个参数传入通常函数 sort/2 的返回值类型与期待不符：期待「布尔」，实际「整数」。`;
  a comparator error aborts the whole sort with that error:
  `sort([2, 1], |$a, $b| 1 // 0)` → `操作 “1 // 0” 非法：除数不能为零`.
  After the first error no further user code runs (both implementations
  stash the first error and finish the sort internally).
- **Laziness**: elements are passed to the comparator **unforced** (like
  `map`) — `count(sort([1 // 0, 2], |$a, $b| true))` → `2`. The result list
  holds the same handles, reordered.

### `reverse/1`

- **Signature**: `reverse(list)` → `list` (eager list).
- **Happy path**: new list, handles reversed. `reverse([1, 2, 3])` →
  `[3, 2, 1]`; `reverse([])` → `[]`; `reverse([1])` → `[1]`.
- **Laziness**: elements unforced — `head(reverse([1 // 0, 2]))` → `2`.

### `concat/2`

- **Signature**: `concat(list1, list2)` → `list` (both eager lists).
- **Happy path**: handle-level concatenation. `concat([1], [2, 3])` →
  `[1, 2, 3]`; `concat([], [])` → `[]`; either side may be empty.
- **Laziness**: elements unforced.

### `prepend/2`

- **Signature**: `prepend(list, el: $lazy)` → `list` (mirrors `append/2`).
- **Happy path**: `[el, ...list]`. `prepend([2, 3], 1)` → `[1, 2, 3]`;
  `prepend([], 1)` → `[1]`; `prepend([1], [true])` → `[[true], 1]`.
- **Laziness**: the prepended element stays an unforced handle —
  `at(prepend([1], 1 // 0), 1)` → `1` (touching position 1 never evaluates
  position 0).

### `at/3`

- **Signature**: `at(list, index: integer, default: $lazy)` → element
  (declared lazy, like `at/2`).
- **Happy path**: in-bounds element access with a fallback. `at([10, 20], 0,
  0)` → `10`; `at([10, 20], 1, 0)` → `20`.
- **Edges**: out-of-range (or negative) indices **never error** — the
  default is returned instead: `at([10, 20], 5, 7)` → `7`; `at([10, 20],
  -1, 7)` → `7`; `at([], 0, 7)` → `7`. (Contrast the unchanged `at/2`,
  which errors out of range with key 43
  `访问列表越界：列表大小为 L，提供的索引为 I`.)
- **Laziness**: the selected value is returned **unforced** — either the
  element or the default. The default is forced only when actually chosen:
  `at([1], 0, 1 // 0)` → `1`, while `at([1], 5, 1 // 0)` →
  `操作 “1 // 0” 非法：除数不能为零`.
- **RNG**: a dice default draws only when used, aligned with the shared
  stream — `at([1], 5, d6)` equals that seed's first `d6` roll.

### `duplicate/2`

- **Signature**: `duplicate(value: $lazy, count: integer)` → `list`.
- **Happy path**: `count` copies of the **same** value.
  `duplicate(1, 3)` → `[1, 1, 1]`; `duplicate(true, 2)` → `[true, true]`.
- **Owner's call (pinning)**: the value is **pinned** (regular-function
  semantics) — every copy wraps the same unevaluated handle, so the value
  is evaluated **once**: `duplicate(d6, 3)` rolls **once** and yields
  `[x, x, x]`, hence `sum(duplicate(d6, 3))` = 3 × that seed's first roll.
  `#` remains the re-evaluating construct: `3#d6` rolls three times (the
  contrast is pinned per seed; the sums generally differ).
- **Edges**: `count ≤ 0` → `[]` (`duplicate(1, 0)`, `duplicate(1, -2)`).
  The shared value is forced only when a copy is forced:
  `count(duplicate(1 // 0, 2))` → `2`, but casting the result forces it →
  `duplicate(1 // 0, 2)` → `操作 “1 // 0” 非法：除数不能为零`. (naive
  wraps the shared box in per-position lazy boxes to avoid registering its
  error beacon twice — implementation detail.)

### `flatten/2`

- **Signature**: `flatten(list, depth: integer)` → `list` (both eager).
- **Happy path**: flatten nested lists up to `depth` levels.
  `flatten([1, [2, [3]]], 1)` → `[1, 2, [3]]`; with depth `2` → `[1, 2, 3]`;
  `flatten([[[1]]], 1)` → `[[1]]`; a depth deeper than the nesting is fine:
  `flatten([1, [2], [[3]]], 5)` → `[1, 2, 3]`.
- **Edges**: `depth ≤ 0` → shallow handle copy: `flatten([1, [2]], 0)` →
  `[1, [2]]`; `flatten([1, [2], [[3]]], -1)` → `[1, [2], [[3]]]`.
- **Laziness & forcing (the depth boundary)**: every element *above* the
  boundary is forced (with implicit casts) to test listness; lists splice
  their handles (recursing with `depth − 1`); non-lists keep their
  **original memoized handle** (no double evaluation); elements **at** the
  boundary stay unforced. So:
  - `count(flatten([[1 // 0]], 1))` → `1` (boundary: not forced);
  - `flatten([[1 // 0]], 2)` → `操作 “1 // 0” 非法：除数不能为零` (above
    the boundary: forced, error propagates);
  - `flatten([[d6]], 1)` draws **nothing**, while `flatten([d6], 1)` draws
    once (the `sequence$sum` element casts to its sum — a leaf):
    `flatten([d1], 1)` → `[1]`.
  - Cast rule at the test: a `sequence$sum` element casts to its sum (a
    leaf — `flatten([2d1], 1)` → `[2]`); a plain-sequence element casts to
    its list and **splices** (`flatten([3#d1], 1)` → `[1, 1, 1]`).

### `flattenAll/1`

- **Signature**: `flattenAll(list)` → `list` (eager list).
- **Happy path**: `flatten` with unbounded depth (iterative DFS, same
  forcing rules). `flattenAll([1, [2, [3, [[4]]]]])` → `[1, 2, 3, 4]`;
  `flattenAll([1, [true]])` → `[1, true]`; `flattenAll([])` → `[]`.
- **Edges / laziness**: unbounded means **every leaf is eventually forced**:
  `flattenAll([[1 // 0]])` → `操作 “1 // 0” 非法：除数不能为零`.
- **Naming flag**: `flattenAll` is the name per #18's table; the issue notes
  「名字还没完全定下来」— still the owner's call to confirm before the final
  docs.

### `flatMap/2`

- **Signature**: `flatMap(list, f: callable)` → `list` (both eager).
- **Happy path**: like `map` then a depth-1 flatten. `flatMap([1, 2], |$x|
  [$x, $x])` → `[1, 1, 2, 2]`; `flatMap([], |$x| [$x])` → `[]`;
  `flatMap([1, 2], |$x| [])` → `[]`. Only ONE level is flattened:
  `flatMap([1], |$x| [[], [$x]])` → `[[], [1]]`.
- **Result must be a list** (after implicit casts) — a plain-sequence
  result casts fine: `flatMap([1], |$x| drop(3d1, 1))` → `[1, 1]`; a
  `sequence$sum` result casts to an integer — still the wrong type:
  `flatMap([1], |$x| d6)` → key 48, position 2:
  `作为第 2 个参数传入通常函数 flatMap/2 的返回值类型与期待不符：期待「列表」，实际「整数」。`
  (same message for a plain integer result, `flatMap([1], |$x| $x)`).
- **Edges**: an `f` error aborts the whole call (no partial result):
  `flatMap([1, 2], |$x| 1 // 0)` → `操作 “1 // 0” 非法：除数不能为零`.
- **Laziness**: each element is passed to `f` unforced; the inner lists'
  element handles are appended **unforced**:
  `count(flatMap([1], |$x| [1 // 0, $x]))` → `2`.

## Element access (`last` / `init`)

> Not in the contracts doc's per-builtin sections (ABI ids 55/56 only);
> empty-list behavior reuses key 44 like `head`/`tail`.

### `last/1`

- **Signature**: `last(list)` → element (declared lazy; eager list).
- **Happy path**: the final element handle, unforced. `last([1, 2, 3])` →
  `3`; `last([1 // 0, 2])` → `2` (the errored first element is untouched).
- **Edges**: empty → key 44 `列表为空` (`last([])`).

### `init/1`

- **Signature**: `init(list)` → `list` (eager list).
- **Happy path**: everything but the last element, handles kept:
  `init([1, 2, 3])` → `[1, 2]`; `init([5])` → `[]`.
- **Edges**: empty → key 44 `列表为空` (`init([])`).
- **Laziness**: elements unforced — `last(init([1, 1 // 0]))` → `1`.

## Folds / unfolds

### `foldl/3`

- **Signature**: `foldl(list, init: $lazy, f: callable)` → value (declared
  lazy; list and callable eager).
- **Happy path**: left fold, `f(acc, elem)`. `foldl([1, 2], 10, |$acc, $e|
  $acc - $e)` → `7` ((10−1)−2); `foldl([1, 2, 3], 0, |$acc, $e| $acc +
  $e)` → `6`; `foldl([1, 2, 3], 0, |$acc, $e| $e)` → `3`.
- **Edges**: empty list → the `init` handle returned unforced:
  `count([foldl([], 1 // 0, |$acc, $e| 0)])` → `1`. An error at any step
  stops the fold and is the result: `foldl([1, 1 // 0, 3], 0, |$acc, $e|
  $acc + $e)` → `操作 “1 // 0” 非法：除数不能为零`.
- **Laziness**: **strict accumulator** — the acc is forced as part of every
  step (bounded thunk chains; compat.md #6). Element handles stay unforced
  (unless `f` forces them). Consequence for RNG: each step draws whatever
  the closure body forces, strictly one step at a time — the draw order is
  the body's own evaluation order (element vs acc), identical in both
  implementations (pinned agreement row `foldl([d2, d100], d1000, |$acc,
  $e| $e * 100000 + $acc)`).

### `foldr/3`

- **Signature**: `foldr(list, init: $lazy, f: callable)` → value (declared
  lazy; list and callable eager).
- **Happy path**: right fold, `f(elem, acc)` — built right-to-left as
  nested lazy calls. `foldr([1, 2], 0, |$e, $acc| $e - $acc)` → `-1`
  (1 − (2 − 0)); `foldr([1, 2, 3], 0, |$e, $acc| $e + $acc)` → `6`; empty
  list → the `init` handle unforced.
- **Laziness**: foldr itself **never forces the accumulator** — the closure
  decides: `foldr([1, 2], 1 // 0, |$e, $acc| $e)` → `1` (the erroring init
  is never touched).
- **Draw/forcing order — pinned in v0.7**: bodies execute **outer-in**
  (leftmost element first) as the final result is forced. With dice in
  elements/init, `foldr([d2, d100], d1000, |$e, $acc| $e - $acc)` draws
  `d2`, then `d100`, then `d1000` (innermost init last); both
  implementations agreed post-fix on seeds 0/1/42. (naive's closure
  machinery forces bodies at call time, so its `foldr` wraps each deferred
  call in an extra lazy box to preserve this order — deliberate, left in
  place.)
- **Depth caution**: deep foldr chains overflow **both** implementations at
  force time (nested value-call forcing defeats the trampoline, compat.md
  #6) — keep chains ≲10³.

### `iterate/2`

- **Signature**: `iterate(start: $lazy, f: callable)` → `sequence` (plain,
  NOT `$sum`; **infinite**). Callable eager.
- **Happy path**: the infinite stream `start, f(start), f(f(start)), …`.
  Item 0 = `force(start)` at the **first pull**; item i+1 =
  `force(f(item_i))` — **strict per pull**: each item is forced and
  memoized before the next step runs (so a deep `take` never chases an
  N-deep thunk chain; compat.md #6). Consume with `take`/`drop`:
  `iterate(1, |$x| $x + 1) |> take(5)` → `[1, 2, 3, 4, 5]`;
  `sum(iterate(1, |$x| $x + 1) |> take(3))` → `6`;
  `iterate(1, |$x| $x + 1) |> drop(2) |> take(2)` → `[3, 4]`.
- **Edges / laziness**: `take(0)` pulls nothing — `iterate(1, |$x| $x + 1)
  |> take(0)` → `[]` (start never forced, no error, no draw). An `f` error
  is a **terminal error item** (yielded once, marked last; the stream ends
  after it, mirroring the reroll/explode rule): `iterate(1, |$x| 1 // 0)
  |> take(2)` → `操作 “1 // 0” 非法：除数不能为零`.
- **Sequence semantics**: never cast an infinite `iterate` to a list (top
  level, `sum`, list-arg builtins, …) — the consumption is unbounded: nova
  dies with its memory-limit error, naive hangs. The suites and fuzzer
  never generate that shape.

### `unfold/2`

- **Signature**: `unfold(seed: $lazy, f: callable)` → `sequence` (plain,
  NOT `$sum`). Callable eager.
- **Step protocol (owner's call — Elixir `Stream.unfold/2` adapted; dicexp
  has no nil)**: per pull, force the current seed, call `f` on it, force
  the result:
  - `false` → the stream **actually ends**. A finite unfold casts to
    exactly its items: `unfold(2, |$n| at([false, [$n, $n - 1]], count([$n],
    |$e| $e > 0)))` → `[2, 1]`.
  - a list of **exactly two elements** → yield `pair[0]` **unforced**, and
    continue with `pair[1]` as the next seed (forced at the *next* pull).
    `unfold(3, |$n| [$n, $n - 1]) |> take(3)` → `[3, 2, 1]`; Fibonacci:
    `unfold([0, 1], |$p| [at($p, 0), [at($p, 1), at($p, 0) + at($p, 1)]])
    |> take(5)` → `[0, 1, 1, 2, 3]`.
  - anything else → a **terminal error item** (stream ends after it):
    - wrong type → key 51: `unfold(1, |$x| 42) |> take(3)` →
      `传入 unfold/2 的闭包的返回值类型与期待不符：期待「布尔」或含两个元素的列表，实际「整数」。`
      — note `true` is ALSO a step error, reported as type `布尔`:
      `unfold(1, |$x| true) |> take(1)` → `…实际「布尔」。`
    - wrong list length → key 52: `unfold(1, |$x| [1, 2, 3]) |> take(3)` →
      `传入 unfold/2 的闭包返回的列表应含两个元素，实际含 3 个。`
      (empty list: `…实际含 0 个。`)
  - an `f` (or seed) error → terminal error item too: `unfold(1, |$x| 1 //
    0) |> take(1)` → `操作 “1 // 0” 非法：除数不能为零`.
- **Laziness**: the seed is forced only at the first pull —
  `unfold(1 // 0, |$x| false) |> take(0)` → `[]` (never forced),
  `unfold(1 // 0, |$x| false) |> take(1)` → the division error. Yielded
  elements stay unforced: `count(unfold(1, |$x| [1 // 0, false]) |>
  take(1))` → `1`.
- **Conditional termination — the simulated-if idiom** (NO trailing `.()` —
  a plain value is not callable):
  `unfold(3, |$x| head(append(filter([[$x, $x - 1]], |_| $x > 0), false)))
  |> take(5)` → `[3, 2, 1]`.
- **Interplay with `drop`**: drop's lazy skip pulls and silently discards a
  skipped terminal-error item — `unfold(1, |$x| 42) |> drop(1) |> take(1)`
  → `[]` (the step error is swallowed with the skipped position).
- **Sequence semantics**: same warnings as `iterate` — an infinite unfold
  (one that never steps to `false`) must never be cast to a list
  (unbounded); always bound it with `take`/`drop` first.

## Take / drop family

### `take/2`

- **Signature**: `take(listOrSequence: list | sequence | sequence$sum, n:
  integer)` → **`list`** (first parameter eager — the list/stream value is
  forced and type-checked, elements/items stay lazy).
- **Accepts BOTH lists and sequences**; always returns a list.
  - **List**: the first `min(n, len)` handles. `take([1, 2, 3], 2)` →
    `[1, 2]`; `take([1], 5)` → `[1]`; `take([], 2)` → `[]`.
  - **Sequence**: pulls `n` **actual** positions (the nominal-last marker is
    deliberately ignored — infinite sources keep drawing past their nominal
    end), collecting the items unforced; stops early if the stream actually
    ends. `take(d1, 3)` → `[1, 1, 1]` (nominal length 1!); `take(3d1, 2)`
    → `[1, 1]`; `take(3#d1, 2)` → `[1, 1]`; `count(take(d6, 3))` → `3`
    (three real draws).
- **Edges**: `n ≤ 0` → `[]` pulling **nothing** (no RNG):
  `take(3#d6, 0)` → `[]`, `take(d6, -1)` → `[]`.
- This is the intended consumer for `iterate`/`unfold`
  (`iterate(1, |$x| $x + 1) |> take(5)`).

### `drop/2`

- **Signature**: `drop(listOrSequence: list | sequence | sequence$sum, n:
  integer)` → **list or sequence** (dynamic return type; first parameter
  eager).
- **Accepts BOTH lists and sequences**; the return kind matches the input
  kind.
  - **List**: a new list of the handles from index `min(n, len)`.
    `drop([1, 2, 3], 1)` → `[2, 3]`; `drop([1, 2, 3], 5)` → `[]`;
    `drop([], 3)` → `[]`.
  - **Sequence**: a **new plain sequence** that lazily skips `n` pulls.
    Nothing is pulled at construction (`count([drop(d6, 1)])` → `1`);
    each skipped position is a **real pull** (a dice draw) only when the
    result is pulled — `drop(d6, 2) |> take(1)` yields exactly that
    stream's **third** draw. The source's nominal-last markers pass
    through (they shift accordingly): `drop(3d1, 1)` cast to a list gives
    the 2nd and 3rd of the three nominal rolls → `[1, 1]`;
    `take(drop(5#d1, 2), 2)` → `[1, 1]`. **`$sum`-ness is dropped**: the
    result is always a plain (non-`$sum`) sequence.
- **Edges**: `n ≤ 0` → the input itself (list: a copy; sequence: the **same
  stream value**) — `drop(d1, 0) |> take(2)` → `[1, 1]`.
- Also silently discards a skipped terminal-error item (see `unfold/2`).

### `takeWhile/2`

- **Signature**: `takeWhile(list, f: callable)` → `list` (both eager).
  **List-only** — sequence forms are a documented follow-up candidate, not
  in v0.7.
- **Happy path**: keeps element handles while the predicate holds.
  `takeWhile([1, 2, 3], |$x| $x < 3)` → `[1, 2]`; `takeWhile([1, 2, 3],
  |$x| true)` → `[1, 2, 3]`; `takeWhile([2, 1], |$x| $x < 2)` → `[]`;
  `takeWhile([], |$x| true)` → `[]`.
- **Edges**: a non-boolean predicate result → key 48, position 2:
  `takeWhile([1], |$x| $x)` →
  `作为第 2 个参数传入通常函数 takeWhile/2 的返回值类型与期待不符：期待「布尔」，实际「整数」。`;
  a predicate error is the whole call's error: `takeWhile([1, 2], |$x| 1 //
  0)` → `操作 “1 // 0” 非法：除数不能为零`.
- **Laziness**: elements are passed to `f` unforced; `f` **stops being
  called** at the first `false` — elements past the stop are never touched:
  `takeWhile([1, 3, 1 // 0], |$x| $x < 2)` → `[1]` (the errored tail is
  safe); `takeWhile([0, 1 // 0], |$x| $x > 0)` → `[]`.

### `dropWhile/2`

- **Signature**: `dropWhile(list, f: callable)` → `list` (both eager).
  **List-only** (same deferral as `takeWhile`).
- **Happy path**: skips while the predicate holds; from the first `false`
  (or the end of the list) the **rest is kept as unforced handles** — `f`
  is never called on them. `dropWhile([1, 2, 3], |$x| $x < 3)` → `[3]`;
  `dropWhile([1, 2, 3], |$x| true)` → `[]`; `dropWhile([1, 2, 3], |$x|
  false)` → `[1, 2, 3]`; `dropWhile([], |$x| true)` → `[]`.
- **Edges**: identical predicate rules — `dropWhile([1], |$x| $x)` → key 48
  (`…dropWhile/2…期待「布尔」，实际「整数」。`); `dropWhile([1], |$x| 1 //
  0)` → the predicate error.
- **Laziness**: `count(dropWhile([1, 3, 1 // 0], |$x| $x < 2))` → `2` (the
  errored element past the stop is kept, unforced and untouched).

## Operators

### `<` / `>` / `<=` / `>=` (altered)

- **Signature**: unchanged arity/precedence; both operands now have
  declaration spec `{integer, boolean}` (previously integers only).
- **What changed — booleans are comparable**: same-type operands compare,
  with booleans ordered `false < true`. `false < true` → `true`; `true <
  false` → `false`; `true > false` → `true`; `true >= false` → `true`;
  `true <= true` → `true`; `false < false` → `false`; `false >= false` →
  `true`. Integers compare numerically as before; no other behavior of
  these operators changed.
- **Mixed operand types error** with the `==`/`!=` rule (key 42, the bare
  rendered operator as parameter): `1 < true` and `true < 1` →
  `操作 “<” 非法：两侧操作数的类型不相同` (likewise `>`/`<=`/`>=`).
  Note `==`/`!=` **already** accepted both integers and booleans — this
  change brings the ordering operators in line with them (the `sort/1`
  precedent).
- **Edges**: operands outside `{integer, boolean}` keep the ordinary
  call-argument-type-mismatch error (`([1]) < (1)`).
- Both operands are forced (no short-circuit — these are ordinary operators).
