# v0.7 builtin contracts

> Semantics contracts for the builtins added in v0.7 (roadmap: builtin
> completeness). These builtins are **new in both implementations** (issue
> #18's ❌/部分 entries exist in neither naive nor nova), so the semantics
> here are *defined* by this document — pinned by design decision, not by
> empirical probing of naive (there is nothing to probe). Where an existing
> naive behavior/convention is reused, it is cited. Per the owner's v0.7
> directive, naive gains the same builtins so the shared suites need no new
> per-impl conditionals beyond the divergence tags that mirror `compat.md`.
>
> Both implementations MUST produce identical observable behavior (values,
> error messages, RNG consumption) for everything here unless an explicit
> divergence tag is named. zh strings quoted below are exact.

## Decisions at a glance (owner-visible judgment calls)

- `if/*` is **not implemented** this iteration — owner's call (2026-10-07):
  it will come together with statements and Elixir-style sugars
  (`if foo do … end`). The shared-suite `if/3` Y-combinator row stays
  `todoFor` nova.
- `has?/2`: scanned elements must be `integer`/`boolean` (strict,
  dicexp-style); a *scalar* element of the other scalar type is simply
  unequal (no error, unlike `==`). Scanning short-circuits on the first
  match — elements past it are never forced (new in both impls, so no
  divergence).
- `min/1`/`max/1`: integer lists only (aggregation, like `sum`/`product`),
  empty list → `列表为空`. Booleans are NOT accepted (unlike `sort/1`).
- `sort/2` comparator: `f(x, y) -> boolean`, `true` = "x comes no later
  than y" (Elixir-style `<=`), stable sort. **The comparator must be
  pure** — comparison order/count differs between implementations
  (V8 TimSort vs Rust driftsort), so RNG-consuming or erroring comparators
  are unspecified; suites only pin pure comparators and always-erroring
  ones (same error value regardless of pair).
- `duplicate/2` pins its value (regular-function semantics): the SAME
  handle is repeated, so `duplicate(d6, 3)` rolls once and yields
  `[x, x, x]` — resolving #18's open question in favor of consistency with
  other regular functions (`#` remains the re-evaluating construct).
- `flattenAll/1` is the name (per #18's table; "名字还没完全定下来"
  noted — flag to owner).
- `unfold/2` step protocol (Elixir `Stream.unfold/2` adapted, dicexp has
  no nil): the closure returns `false` to end the stream, or a list of
  exactly two elements `[element, nextSeed]` to continue. Anything else is
  a step error (new keys 51/52).
- `iterate/2`, `unfold/2` return plain (non-`$sum`) infinite/finite
  sequences. They are **strict per pull**: each produced accumulator/item
  is forced (memoized) before the next step is computed — otherwise the
  final force chases an N-deep nested chain and overflows (~compat #6's
  trampoline note; a lazy accumulator must be forced at every level).
- `take/2`/`drop/2` are extended to sequences SOLELY to make
  `iterate`/`unfold` consumable (`iterate(1, |$x| $x+1) |> take(5)`).
  `takeWhile`/`dropWhile` stay list-only for 1.0 (sequence forms are a
  follow-up candidate; flag to owner).
- `drop/2` on a sequence returns a new **plain** sequence (never `$sum`),
  lazily skipping `n` pulls.
- Casting an infinite sequence (`iterate`, never-ending `unfold`) to a
  list (top level, `sum`, list-arg builtins, …) is unbounded: nova dies
  with its memory-limit error (compat #7), naive hangs (worker hard
  timeout). Suites never exercise that shape; fuzzer never generates it.
- naive's `flattenListAll` indexing bug (compat #9 bullet 1) is **fixed in
  naive** this iteration (one-line: `values.push` instead of
  `values[i] =`), so naive's `any?/1` on nested lists and the new
  `flattenAll/1` agree with nova. The div9 tag for that bullet is retired
  (rows re-pinned to the fixed behavior). The OTHER div9 bullets stand.
- naive's `any?/1` keeps its eager element forcing (changing it is beyond
  "adding missing counterparts"); `all?/1` mirrors the per-impl split:
  naive eager-flatten, nova short-circuit at the first `false` — the
  existing `div1-short-circuit` tag covers the sensitive rows. (Making
  naive's `any?`/`all?` short-circuit too would retire div1 entirely —
  owner's call, flagged.)
- Comparison operators `<` `>` `<=` `>=` accept booleans in BOTH impls
  (#18's "应该也允许布尔值之间"; `sort/1` precedent). Mixed int/bool
  operands error with the `==`/`!=` message shape:
  `操作 “<” 非法：两侧操作数的类型不相同` (key 42, rendered op param).

## Per-builtin contracts

Conventions: "forces" = force + error-propagate; "implicit casts" = the
unwrap machinery's sequence casts (sequence$sum→integer, sequence→list)
apply when the target spec doesn't include the sequence type — this is
both impls' existing rule for list-typed params (so e.g. `sum(3#d6)` and
`min(3#d6)` Just Work). Returned lists copy element HANDLES (elements
stay lazy) unless stated otherwise.

### Scalar / utility

- `abs/1` (int) → int. `abs(-9007199254740991)` = `9007199254740991`.
- `count/1` (list) → int. Length WITHOUT forcing elements:
  `count([1//0, 2])` = 2. (naive's error-beacon poisoning can still fire
  on poisoned lists — div9-tagged rows only.)
- `has?/2` (list, x:int|bool) → bool. x eager (decl spec
  `{integer, boolean}`). Forces elements left-to-right with implicit
  casts; a non-scalar element → key 50; a scalar cross-type element is
  unequal (no error); first match → `true`, remaining elements never
  forced. Empty → `false`.
- `min/1`, `max/1` (list) → int. Empty → key 44 `列表为空`. Elements
  forced left-to-right with implicit casts; non-integer → key 45.
- `all?/1` (list) → bool. Flatten-DFS like `any?/1`; non-boolean → key
  46; empty → `true`. **div1**: nova short-circuits at the first `false`
  (compat #1); naive flattens eagerly (its `any?/1` style). Note: naive's
  DFS uses the FIXED `flattenListAll` (see "naive-side changes").

### Ordering / list reshaping

- `sort/2` (list, f) → list. Elements passed to f UNFORCED (like `map`);
  f's result forced per comparison; non-boolean → key 48 (pos 2,
  `sort/2`, 期待「布尔」). Stable; pure-comparator-only contract above.
  Error from f aborts the sort with that error.
- `reverse/1` (list) → list, handles reversed.
- `concat/2` (list, list) → list, handles concatenated.
- `prepend/2` (list, el L) → list `[el, ...list]` — mirrors `append/2`
  (el stays an unforced handle).
- `at/3` (list, index:int, default L) → element handle UNFORCED when
  `0 ≤ index < len`, else the default handle UNFORCED. Never errors on
  OOB. (`at/2` unchanged: OOB → key 43.)
- `duplicate/2` (value L, count:int) → list of `count` copies of the SAME
  handle (pinned; `duplicate(d6, 3)` rolls once). `count ≤ 0` → `[]`.
- `flatten/2` (list, depth:int) → list. `depth ≤ 0` → shallow handle
  copy. Otherwise each element reachable above the depth boundary is
  forced (with implicit casts) to test listness; lists splice their
  handles (recursing with depth−1); non-lists keep their ORIGINAL handle
  (memoized — no double evaluation); elements AT the boundary stay
  unforced. Element errors propagate. So `flatten([d6], 1)` draws,
  `flatten([[d6]], 1)` does not.
- `flattenAll/1` (list) → list = flatten with unbounded depth (iterative
  DFS, same forcing rule — every element is eventually forced).
- `flatMap/2` (list, f) → list. Like `map` then depth-1 flatten: per
  element, call f (element unforced), force the result; error → the whole
  call errors (stops; no partial result); result must be a list (after
  implicit casts) else key 48 (pos 2, `flatMap/2`, 期待「列表」); inner
  element HANDLES are appended unforced.

### Folds / unfolds

- `foldl/3` (list, init L, f) → value. `f(acc, elem)`; acc forced after
  EVERY step (strict accumulator — bounded thunk chains, compat #6);
  elem handles unforced. Error → stops, error is the result. Empty list →
  the init handle unforced.
- `foldr/3` (list, init L, f) → value. `f(elem, acc)`; acc NOT forced by
  foldr (the closure decides). Built right-to-left as nested lazy calls;
  deep chains overflow BOTH impls at force time (nested value-call
  forcing defeats the trampoline, compat #6) — suites keep foldr chains
  shallow (≲10³).
- `iterate/2` (start L, f) → plain `sequence`, infinite. Item 0 =
  force(start) at first pull; item i+1 = force(f(item_i)) at pull i+1
  (strict per pull, memoized per position like all nova/naive streams).
  f error → terminal error item (marked last; stream ends after) —
  mirrors the reroll/explode terminal-error rule.
- `unfold/2` (seed L, f) → plain `sequence`. Per pull: force(f(acc));
  `false` → stream ENDS (actual end); a 2-element list → yield element
  (pair[0] handle, UNFORCED) and continue with acc = force(pair[1]);
  anything else → key 51/52 as a terminal error item; f error → terminal
  error item. Casting a finite unfold to a list yields exactly its items.

### Take/drop family

- `take/2` (list|sequence, n:int) → LIST. n ≤ 0 → `[]` (pulls nothing —
  no RNG). List: first min(n, len) handles. Sequence: pulls n actual
  positions (or until the stream ends), collecting the items — pulls past
  the nominal end where the source is infinite (dice/repeat keep drawing;
  `take(d6, 3)` = 3 rolls).
- `drop/2` (list|sequence, n:int) → list-or-sequence. n ≤ 0 → the input
  (list: copy; sequence: same stream). List → list of handles from index
  min(n, len). Sequence → a NEW plain sequence that skips n pulls lazily
  (nothing pulled at construction; RNG only when the result is pulled);
  nominal-last markers shift accordingly (pass-through of the source's
  status at position skip+i); `$sum`-ness is dropped.
- `takeWhile/2` (list, f) → list. Call f per element handle (force
  result; non-boolean → key 48 pos 2 `takeWhile/2`); keep handles while
  `true`; STOP at the first `false` or error (error → whole call errors);
  elements past the stop are never touched.
- `dropWhile/2` (list, f) → list. Skip while f is `true` (same per-call
  rules, `dropWhile/2`); from the first `false`/stop, keep the REST as
  unforced handles (f is never called on them). Error → whole call errors.

### Operators

- `<`/`>`/`<=`/`>=`: both operands forced with decl spec
  `{integer, boolean}`; different operand types → key 42 with the bare
  rendered operator (`<`, …) — `操作 “<” 非法：两侧操作数的类型不相同`;
  same type → compare (`false < true`). No other behavior change.
